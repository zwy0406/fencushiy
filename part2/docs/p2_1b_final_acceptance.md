| 要求 | 核验 |
|---|---|
| A 固定种子关闭对照 | 原 Simulator 与空受控集合比较移动类型、位置、推进能耗、网络快照和包生成及交付时间。 |
| B 单一位置写入者 | 受控节点只有 MovementController，未受控节点使用 Gauss–Markov。Part2 实例拒绝 replay 模式，避免同时启用两个写入者。 |
| C 物理与网络时钟 | 两节点用例逐 100 ms 核对位移及运动时钟，并核对快照时间每 1 s 前进。 |
| D CH 变化 | P2-0 单元测试验证更换 CH 和簇编号后任务群 ID 保持。12 秒短测的 CH 和成员划分均保持，因此该短测不作为 CH 更换证据。 |
| E 故障、退出、失联 | 三节点夹具验证显式候选交接给仍具独立路径的备用节点。共享故障簇头的最小复现也保留，备用节点没有可用路径时有效覆盖为空。 |
| F/G PoI 与路由口径 | 两名可达服务 UAV 覆盖同一 PoI 只计一次。失联后几何覆盖和有效覆盖分开报告。 |
| H PDR | 对唯一包 ID 的逐包结果计算，重复 ID 拒绝，空生成集合返回空值。短测与 Simulator 的生成计数及交付 ID 集合大小交叉核对。 |
| I 能耗 | 逐节点核对电池损耗 = 推进 + 通信，通信 = 数据 + 控制 = TX + RX。 |
| J 跨通信边界 | 受控 UAV 移动跨越范围，旧快照仍有路径时实时几何检查已将其判为不可用。 |

## 12 秒多节点闭环

固定布局、seed 2025、6 架 UAV 加 1 个 BS，使用冻结 Proposed 方法和现有逐包诊断。UAV 1 受控，其他 5 架 UAV 保留 Gauss–Markov。两个显式 PoI 任务，3 s 动作请求 100 m，经 20 m/s 限速后执行 60 m。业务由真实仿真事件产生。该场景用于验收接口。

| 指标 | 实测 |
|---|---|
| 网络与轨迹 | 12 次网络快照，840 条 100 ms 节点轨迹。CH 始终是 1、4，记录保留簇成员、BR 和 BS 路径。 |
| UAV 1 可达性 | 约 2.2 s 从可达变为不可达，原始状态精度 100 ms。 |
| PoI | 111 个样本。几何/有效覆盖率分别为 100%/100% 共 6 个、50%/50% 共 5 个、100%/0 共 99 个、0/0 共 1 个。最后一种是任务下发前的采样点。 |
| PDR | 338 个唯一生成包，247 个真实交付，截止 12 s 为 **73.08%**。78 个包仍未完成，另有 12 个迁移耗尽和 1 个重试耗尽。分母包含截止点前全部生成包，包含仍未完成者。 |
| 发送证据 | 571 条 hop 记录，其中 454 条有发送开始时间。 |
| 能耗 | 推进 81,350.975861 J，通信 0.4108144 J，其中数据 0.4037584 J、控制 0.0070560 J。单节点账本最大绝对误差约 1.82×10⁻¹¹ J。 |

逐包、轨迹、覆盖、路径及账本在 [smoke_12s](../acceptance/smoke_12s)。在已集成源码根目录运行 `python -m part2.p2_1b_smoke <新输出目录>` 可复跑。PDR 的唯一输入是 `packet_outcomes.csv` 中的唯一包 ID、交付结果和交付时间。BS 可达覆盖是已发布路径与实时链路几何共同判定的代理。

## PyTorch 和候选模块

两项跳过来自 `test_trajectory_training`。本机默认 Python 的 `torch` 只解析为缺少 `cuda` 和版本属性的空命名空间，本机 `mcs`、`LCX` 环境无法导入 torch，本机未找到 `fc`。远端 `fc` 因认证受阻而无法检查。因此本轮未执行候选 Actor/Critic/CVaR 张量测试。

| `3ad62c2` 模块 | 复用与适配 |
|---|---|
| `phycom/networks.py` 的 DeterministicActor 和 CentralCritic | 可用于固定六机的张量契约验证。保留每 agent Actor 和 joint obs/action Critic，核对 2×160、连续双动作及 K=50。新增观测维度后重新核对形状。 |
| `phycom/losses.py` 的 quantile Huber、lower-tail CVaR | 可复用数学实现候选。CVaR 按分位索引切前缀，非整数尾质量做分数加权。下一步验证形状、边界值和梯度。 |
| `phycom/maddpg.py` 的 CTDE 更新 | 可复用 target、逐 agent 更新与软更新结构。候选 τ=0.01，用户提供的论文口径 τ=0.15。 |
| `phycom/replay.py` 的 ReplayBuffer | 可复用固定维度环形缓存和种子管理。可变任务群需稳定 UAV ID、有效 mask、加入退出及 terminal 定义。 |
| AMO 与环境 | 奖励重新定义。论文口径 A2G 28 dBm、AMO 阈值 0.55 且含悬停代价。候选基础配置是 30 dBm、阈值 null 由 pilot 解析，原移动代价无悬停项。历史 28 dBm 悬停配置仍采用阈值 1.4。 |
| UavNetSim 接口 | 由实时网络快照构造观测。方向和位移转换到米、弧度和微秒，并受 `min(d_max,v_max×Δt)` 限制。历史候选决策步 50 s，UavNetSim 物理步 0.1 s、网络维护 1 s，慢层候选 2/3/5 s。 |
