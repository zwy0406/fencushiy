# Part1 → Part2 接口设计（仅设计，不改代码）

## 边界

`TAE-MWMP-DCA` 仍按原 1 s 网络维护周期更新簇与路由，并输出只读 `ClusterSnapshot`、`BackboneSnapshot`、节点能量和通信状态。新增慢层 `ClusterTaskManager`，输出稳定的任务群及观测到 `RS-D-MADDPG`；不回写 Part1 的 CH/BR/簇划分规则。物理位置继续按现有移动积分步更新，任务决策周期与该积分步独立。

## 动态任务群状态

每个任务群存 `task_group_id`（单调分配、不可复用）、`task_group_members`（稳定 UAV ID 集合）、`task_group_anchor`（覆盖区域或任务中心，不等同 CH ID）、`service_uav_ids`、`group_creation_time`、`last_update_time`、`group_status`（active/degraded/reconfiguring/closed）。另存当前簇映射、路径可用性、网络角色快照、PoI 需求及有效成员掩码。网络簇变更时通过成员 Jaccard 与空间/任务连续性候选映射任务群；不能用 `cluster_id` 或 CH ID 直接充当永久任务群 ID。分裂/合并需要显式新旧任务群关系和任务交接记录。

`service_uav_ids` 必须由覆盖任务分配器显式给出，依据可达 PoI、剩余电量、推进与通信预算、到 BS 的可用路由、当前覆盖收益以及 CH/BR 转发负担选取。CH/BR 可以兼任服务 UAV，但须计入双重任务资源；CM 不是天然服务 UAV。服务集合变化应由任务调度决策并记录原因。失败或离网节点须从有效集合与掩码移除，不可由网络角色推断其任务资格。

## 最小可行可变规模策略

保留已发表 RS-D-MADDPG 的风险敏感分布式价值估计、Actor 和 CTDE 学习流程。第一版共享单个 Actor 参数；每架服务 UAV 输入固定维度的自身状态、任务群聚合特征和按稳定 ID 排序的至多 K 个邻居特征，配有效位掩码。集中式 Critic 用同一 K 上限的填充槽位 + 掩码，或在不改风险价值目标的前提下采用掩码池化；超过 K 的任务群先由诊断分布确定拆分/分层规则，不能静默截断。训练数据记录真实 agent 数、槽位映射、有效掩码、加入/退出与终止标志；退出节点的隐状态清除，加入节点初始化 Actor 状态。固定六机原算法作为兼容特例先核对动作/价值输出，再增加可变规模。K 与具体截断规则需用独立开发数据确定，并在正式测试前冻结。

## 周期与事件

正常协同覆盖每 `T_task` 决策一次。候选 2/3/5 s，1 s 为高频参考、10 s 为压力对照；这仅是结构诊断筛选，不等于覆盖性能最优。每秒读 Part1 快照并累积任务群成员 Jaccard、服务可达性、覆盖状态。CH 更换只刷新通信联系人/路由观测，不自动销毁群；只有成员变化持续超过迟滞门槛、PoI 需求改变或服务资源不足才重配任务群。用开发种子选择 `J_min`、连续异常次数 `H`、最短保持时长和重配冷却时间，随后冻结。路径失效须区分快照短暂缺失与持续失联：先局部路由/目标降级，达到事件条件后提前任务决策；真实服务 UAV 故障可立即触发恢复。重配过程保证任务所有权和动作生效时刻明确，避免同一 PoI 重复分配或无主。

## 建议实施顺序与验收

1. 冻结恢复后的 Part1 基线及 R3 日志；记录 `regression-validated reconstruction`，不称为历史源码原样。
2. 在独立 Part2 集成分支实现只读快照适配器和任务群 ID 映射；用合成簇轮换/分裂/合并测试身份连续性，不训练。
3. 实现显式服务 UAV 选择与资源约束，确认 CH/BR 兼任时路由和能量不被隐式忽略。
4. 接入固定六机 RS-D-MADDPG，核验原风险敏感目标和 CTDE 更新；再加掩码式可变规模输入及加入/退出测试。
5. 增加慢周期控制、迟滞、持续路径失效与故障事件；核对无事件时 Part1 网络轨迹与冻结基线一致。
6. 用独立开发种子选周期和迟滞参数，冻结后用留出种子正式评价；不拿 R4-1 seed2025 的诊断结果充当最终性能证据。

R4-2 六组不是实现该接口的必要前提，但跨规模稳定性、事件关联普遍性、任务周期优劣的正式论文论断需要多种子验证。当前未修改 Part1 或 Part2。
